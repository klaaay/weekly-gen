### [Frond — React 应用的前端运行时图谱](https://frondruntime.dev/)

**原文标题**: [Frond — The frontend runtime graph for React apps](https://frondruntime.dev/)

Frond 的核心主张是：React 不是应用运行时，应用本身已有运行时；Frond 把这些分散在 providers、effects 和 cleanup 脚本中的运行时组织成依赖图，由 Effect 执行，React 仍只做渲染。它用图统一管理依赖、身份、就绪、生命周期、清理与错误，让登出等身份变化通过一次 eviction 自动释放所有用户作用域资源。

- 🧠 **定位**：Frond 不是路由、渲染器或组件框架，而是 React 背后的运行时图，管理服务、资源、facade、身份、就绪、生命周期、清理和正确性。
- 🔗 **依赖图**：每个节点声明 key、deps、acquire/release；依赖关系显式化，服务之间不再靠手工清单维护。
- 🚪 **登出/用户切换**：调用 `evict("selfAndDependents")` 即可驱逐所有依赖当前会话的节点，中断进行中工作并执行释放。
- 🧹 **清理归属**：资源由获取它的节点负责释放；驱逐会运行 release、取消进行中任务、清除就绪状态，并拒绝过期提交。
- 🔄 **生命周期优先**：Frond 不止是状态管理；节点是 MobX 可观察对象，但真正价值是回答状态何时可存在、依赖何时就绪、身份变化时如何取消/释放。
- 🛡️ **端到端类型安全**：`dep(ProfileNode)` 携带节点类型，driver 返回值成为 `node.result`，类型沿依赖图传播到 React 消费端，无需手工断言。
- 🧾 **结构化错误**：错误带 kind、tag、retryable 和 cause chain；运行时会遍历因果链生成可序列化报告，按图拓扑分组并接入 Sentry 等 sink。
- ⚙️ **Effect 在底层**：取消、作用域资源、结构化并发、重试等由 Effect 保证；普通使用无需导入 Effect，需要时可切换到 `Frond.Driver.Effect`。
- 🚦 **适用场景**：适合启动有就绪门禁、服务依赖服务、用户身份会使半个应用失效、需要清理 socket/SDK/analytics、页面聚合多资源、需要诊断“为什么没就绪”的应用。
- 🙅 **不太适用**：如果应用主要是独立页面渲染、数据加载局部化、登出只清一个 token/cache、React Query 已能解释大多数异步状态、没有长生命周期前端服务，则可能不需要。
- 🚀 **上手方式**：从一个节点开始，安装 Frond 并编写首个 node。
