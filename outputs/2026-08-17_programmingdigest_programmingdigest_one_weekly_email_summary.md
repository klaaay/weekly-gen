### [压缩即预测 | ngrok 博客](https://ngrok.com/blog/compression-is-prediction)

压缩与语言模型（LLM）在核心上解决的是同一个问题：通过预测符号的概率来减少数据所需的比特数。文章介绍了压缩的基本原理、熵编码器、熵的概念，以及上下文建模如何提升压缩效果，最终论证“压缩即预测”，而 LLM 本质上是强大的压缩器。

- 🧠 压缩与 LLM 本质相同：都是利用符号概率分布来减少表示数据所需的比特数
- ✂️ 压缩不是简单的删减：与 minification 不同，真正压缩依赖数据中的冗余和概率模型
- 🏃 行程编码示例：把连续相同字符转为“字符 + 次数”，如 28 字符字符串可缩至 12 字符，节省 57% 空间
- 🔧 现代压缩器三大部分：变换（transforms）、模型（model）、熵编码器（entropy coder）
- 📊 模型为每个符号提供概率，熵编码器利用这些概率生成最终压缩比特流
- 🔢 算术编码：能把整段数据编码成单个二进制数，区间越窄所需比特越多
- 📉 概率越倾斜，压缩越好：例如 12 字符的“AAAAAAAAAABC”平均每符号仅 0.82 bits，而“ABABAAC”为 1.38 bits
- 🧮 熵是压缩下限：−log₂(概率) 表示理想比特数，其期望值就是无损压缩无法突破的每符号比特下限
- 🌳 Huffman 编码：用决策树为符号分配码字，常见符号用短码、罕见符号用长码，但非二分概率时会有舍入浪费
- 🧩 上下文大幅改变概率：如字母 U 英文整体概率约 0.028，但跟在 Q 后接近 0.999；order-N 模型利用前 N 个字符作为上下文
- 📈 上下文模型效果显著：用 order-1 模型压缩“TO BE OR NOT TO BE”，平均比特从 2.59 降至 1.16 bits/symbol，压缩体积减半以上
- 🤖 LLM 是高级预测器：基于上下文 token 预测下一 token 的概率分布，按真实 token 的概率以 −log₂(p) 计算比特成本
- 📏 模型好坏直接影响压缩率：差模型会给真实 token 低概率，导致大量额外比特；GPT-2 压缩狄更斯引文仅需原大小约 10%，而 order-1 模型需 24%
- ⚖️ 实际应用受限：LLM 压缩需在两端部署巨大模型，且计算开销极高，对普通网页或 HTTP 响应这类任务并不实用
- 🪙 结论：熵编码技术已接近极限，真正能优化的是模型预测能力；LLM 与压缩器是同一数学的两种表达——压缩即预测，LLM 即压缩器

- 🧭 A* 依赖启发式引导搜索，但常见的距离启发式不了解地图结构，有时会把搜索推向错误方向。
- 🎯 理论上存在“完美启发式”，但它依赖具体目标，无法预先计算和存储，实用中不可行。
- 🔺 关键技术：利用三角形不等式 cost(B,X) ≥ cost(B,L) − cost(X,L)，用已计算的地标距离来估计任意目标的下界。
- 📍 单个地标只对“位于地标之前”的目标有效，因此需要多个地标覆盖不同的起点 - 目标组合。
- 📊 多个地标分别给出下界，取最大值作为最终启发式，可显著提高 A* 的搜索效率。
- 🏗️ 地标放置需要按项目定制：需考虑路径出现频率、路径优化价值、地图是否静态，以及地图类型（开放世界或房间 + 走廊）等。
- 🤖 自动放置可通过随机路径分析实现：选择对随机路径贡献最大的位置，并让新地标尽量远离已有地标。
- 🛠️ 实现代码很少：对每个地标运行一次 Dijkstra（或 BFS）反向搜索，存储 cost[node][landmark]，然后修改启发式函数为 max(原启发式，|L_cost[B][i] − L_cost[X][i]|)。
- 🗺️ 在 Dragon Age、Cogmind、迷宫等地图的演示中，该方法减少了需要搜索的节点，蓝色区域表示被优化掉的区域。
- 📄 相关研究包括 2004 年 Goldberg 与 Harrison 的论文、压缩微分启发式，以及更早的网络路由应用等。

**原文标题**: [A Deep (and Fuzzy) Dive Into Search | SereneDB Blog](https://blog.serenedb.com/fuzzy-search-deep-dive)

概述：本文深入探讨 SereneDB 搜索引擎核心 IResearch 中的两种模糊匹配算法：基于 Levenshtein 距离的自动机匹配与基于 n-gram 相似度的匹配，涵盖原理、优化、实现细节、SQL 用法及各自适用场景。

- 🔍 **模糊搜索的动机**：处理拼写错误、语言同源词、DNA 序列比对与记录去重等场景，需要量化两个字符串的接近程度。
- 📏 **Levenshtein 距离定义**：通过插入、删除、替换的最小操作数衡量差异，经典 Wagner–Fischer 算法需 O(|a|·|b|) 时间，不适合大规模词典。
- 🤖 **自动机技巧**：Schulz 和 Mihov 提出为固定编辑距离 n 构建确定性自动机，线性时间构建，与词典 trie 求交时可剪枝整棵子树，避免全量比对。
- 🧩 **NFA 构建**：以 (索引，已用编辑次数) 为状态，包含匹配、插入、替换、删除四类转移；编辑次数增加则进入更高层轨道。
- ⚡ **线性化优化**：通过局部性（每位置最多 2n+1 个活跃状态）、子集吸收（消除指数因子）和参数化（用特征向量表示字符分布）将状态数降为 O(N)。
- 📊 **特征向量与转移表**：特征向量 χ(c,W,I) 标记查询词后续字符出现位置；距离 1 时仅 5 种参数状态，转移表仅 40 项，可复用构建任意查询词的 DFA。
- ⚙️ **实现细节**：IResearch 中 ParameterDescription 负责转移表，MakeLevenshteinAutomaton 生成自动机；支持 Damerau–Levenshtein（相邻换位算一次编辑），更贴近人类输入错误。
- 🚀 **查询流程**：SQL 函数 ts_levenshtein 执行模糊匹配，按 1 - d/min(|V|，|W|) 打分排序；自动模式根据查询长度选择编辑距离，还支持前缀锚定与普通 SQL 条件组合。
- ⚠️ **距离上限与优化**：自动机状态数随 n 爆炸（n=4 时约 69 万转移），因此 Levenshtein 上限为 4，Damerau 为 3；利用反转不变性，可正反双词典实现距离 n+1 查询。
- 💡 **n-gram 相似度动机**：编辑距离存在长度偏差且无法处理多余/缺失单词；基于字符 n-gram 的 LCS 可保留局部上下文，避免无意义匹配（如 connection 与 fonetica）。
- 🧮 **Kondrak 算法**：对 n-gram 序列做 LCS 递归，按较长串归一化得到 [0,1] 分数；无需逐查询自动机，直接利用倒排索引的 n-gram 位置进行两阶段过滤。
- 🔎 **实现差异**：IResearch 的 ngram 查询用 MinMatchCount 计算最少匹配 n-gram 数（k=ceil(|X|·t)），仅按查询长度归一化，因此短查询可匹配长字段，且额外词不扣分。
- 📝 **更精确的评分**：Kondrak 改进版在匹配窗口内计算字符级重合比例，可提升 10–20% 准确率；实现时可对每个 n-gram 构建 Levenshtein 自动机并合并，实现“模糊到底”。
- 🗄️ **SQL 用法示例**：创建 ngram 字典（mingram=2, maxgram=2）后，ts_ngram('hello', 0.3) 可匹配 help、held 等近似词；阈值默认 0.7。
- ⚖️ **总结**：Levenshtein 自动机擅长精确控制“k 个拼写错误”的短词匹配；n-gram 相似度容忍额外/缺失字符，适合长串与部分重叠；两者常结合使用。

**原文标题**: [email encryption](https://computer.rip/2026-07-19-email-encryption.html)

- 🌐 电子邮件兴起于 1960 年代，多源设计并存，最终 ARPANET 体系下的 SMTP/IMAP 成为主流，奠定了现代邮件形态。

- 🔒 现实中绝大多数邮件加密发生在传输层：STARTTLS、DANE、MTA-STS 广泛部署，有效规避降级攻击，却无法保护用户免受邮件服务商窥探。
- 🏥 在医疗等行业，强制配置服务器间 TLS 即可满足合规要求，端到端加密反而被视为对邮件原始设计缺陷的复杂补丁，采用率始终不高。

- 💡 事件指示符不是“喊叫”，而是让你懒得更优雅的命令行复用工具，适用于 bash、zsh 等主流 Shell。
- 🧩 核心结构为`![事件][:词][:修饰符]`，分别指定历史行、参数位置和变换方式。
- 🔁 `!!`可重复上一条命令，配合`sudo !!`能轻松解决权限不足问题。

- ✂️ 修饰符很强大：`:h`取目录部分，`:t`取文件名，`:r`去掉扩展名，`:e`只留扩展名，`:s/old/new/`做替换。
- 🖥️ POSIX 的`fc`命令能在你喜欢的编辑器中修改历史命令后重跑，也支持`fc -s`快速复用与`-e`批量替换。
- 🔑 最值得牢记的“三法则”是`!!`、`!needle`、`!?needle?`；“四强”则是`!$`、`!:0`、`!$:h`、`!$:t`。
- 🛡️ 担心误操作？可开启 bash 的`histverify`或 zsh 的`HIST_VERIFY`，让展开结果先确认再执行；或使用`:p`只打印不运行。
- 📝 历史记录保存的是展开后的实际命令，而不是`!!`这类原样符号。
- 🚫 若想彻底关闭`!`展开，可在 bash 中用`set +H`，在 zsh 中用`setopt nobanghist`，或自定义`histchars`。
- ❓ `ctrl-r`适合搜索但难提取局部参数，`alt-.`只限最后一个参数；事件指示符在组合和引用上更灵活。
- ⚖️ 这不是“非此即彼”，`ctrl-r`、`alt-.`和事件指示符都可以混用，选择最适合自己工作流的才是关键。
