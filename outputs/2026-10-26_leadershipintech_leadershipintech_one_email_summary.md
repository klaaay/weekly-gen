### [如果你的团队很开心，就说明你干得好吗？](https://charity.wtf/p/if-your-team-is-happy-are-you-doing)

**原文标题**: [If your team is happy, are you doing a good job?](https://charity.wtf/p/if-your-team-is-happy-are-you-doing)

overview summary
本文是 Charity Majors 与 Dr. Cat Hicks 关于 AI 时代团队协作的对话第三部分，核心讨论“团队开心是否等于管理成功”。文章指出，心理安全感原本服务于学习、问责与高绩效，却被大众误解为“工作中不应让人难受”；作者批评 ZIRP 时期把员工情绪当作管理目标的做法，强调好领导既要关心人也要懂业务，学习本身常伴随不适，并且人们容易把系统性问题错误归因于个人。

- 🎯 核心问题：如果团队开心，是否就代表管理者做得好？作者认为这经不起推敲，因为管理目标是业务成功与良性结果，而不只是让人感觉良好。
- 🧩 历史转向：Project Aristotle 与 DORA 用数据证明高绩效取决于团队动态，包括心理安全、可靠性、结构与清晰度、意义感和影响力，而非单纯依赖“天才混蛋”式的个人英雄主义。
- ⚠️ 概念漂移：心理安全感被简化成“我永远不该难受”，甚至把坏消息、裁员、未获晋升、建设性反馈都视为心理安全受损；其真正价值在于促进学习，而非回避不适。
- 🧊 ZIRP 管理误区：“团队开心就是好管理”反映了宽松增长时代的管理哲学；但有效领导者应兼具善意与业务能力，不能把员工情绪当作必须管理的业务结果。
- 🍦 幸福辨析：亚里士多德区分 eudaimonia（因充实生活和行动而获得的幸福）与享乐式快乐；无限假期和冰淇淋未必带来真正持久的满足，人也并不擅长预测什么会让自己幸福。
- 📚 学习本质：学习需要自省、扩展边界和暴露脆弱，常常令人不舒服；正因如此，愿意在同事面前承认“不知道”才能建立信任。
- 🗓️ 学习投入：学习活动很难从日历邀请判断价值，回报慢且不确定；应像投资一样提出假设、测试、投入并衡量，而不是盲目“撒钱祈福”。
- ⚖️ 归因偏差：人们倾向于把工作中的快乐或痛苦归因于个人，过度赞扬或责怪管理者，却忽视结构、系统与集体劳动的作用；公平问题需要更多从系统层面审视。
- 🔜 结尾问题：作者问 Cat：衡量公平时应看人还是看系统？下一篇回应将讨论“组织公平是良好问题解决文化的前提”。

### [用 `small-change` 加速代码审查 | 非理性繁荣](https://lethain.com/small-changes/)

**原文标题**: [Speeding up code review with `small-change` | Irrational Exuberance](https://lethain.com/small-changes/)

文章介绍了 Imprint 在 PR 合并量大幅提升、质量改善的同时，代码评审时长从 33 分钟升至 77 分钟并成为瓶颈；团队因此推出 `small-change` 机制，通过 CICD 检查、AI 评审和作者经验等条件筛选低风险小改动，用自动化技能快速批准，并把由此引发的错误视为系统级问题。文章还讨论了“meat proxy review”反模式和集中式 harness `fleet`，早期约 10% 变更符合 `small-change`，最终成败取决于验证能力的持续扩展。

- 📈 工程效率显著提升：Imprint 平均工程师的 PR 合并量是两年前的 4 倍，两个团队达到 10 倍，个别工程师达到 25 倍。
- ✅ 质量同步改善：事故半年环比下降 42%，严重事故下降 78%，说明质量与速度并非简单取舍。
- ⏱️ 评审成为瓶颈：PR 评审中位数从两年前的 33 分钟增至 77 分钟，且与合并 PR 数量高度相关。
- 🧭 重新审视评审目的：知识共享、防错、防恶意行为和合规；现代开发范式下，部分目标可用更好机制替代逐 PR 人工评审。
- 🧩 `small-change` 资格标准：少于 1000 行代码、AI 评审无 p1/p2 问题、作者在相关服务有 10+ 合并经验、影响服务数少于 N（前端为 1，后端为 3），共享库和工具文件不适用。
- ⚙️ 执行机制：CICD 生成 GitHub check 决定资格，标签仅用于可见性；Slack reacji 标识状态；仓库内 `.small_change` 支持按路径定制。
- 🤖 自动化技能：`review-small-change` 只批准或忽略、不发表评论，避免“meat proxy review”；`review-pr-cluster` 批量识别共性问题。初版约两天完成上线，后续长期调参。
- 🧠 文化原则：任何由 `small-change` 引发的错误都应在系统层解决，改进 AI 评审、验证机制、CICD 和 harness。
- 🚫 “meat proxy review”反模式：让 harness 生成大量评论、再用 harness 回复，形成没有学习价值的评审幻觉；应投资集中评审机制并直接批准。
- ☁️ `fleet`：集中编排的云端 harness，用独立评估决定所需评审人数，安全变更可仅需 1 人评审。
- 📊 早期结果：约 10% 变更符合 `small-change`，可获得快速批准，除非涉及安全或资金等敏感主题；未来需扩大比例并增强验证。
- 💬 接受度：变革让部分人不适，需要持续重新评估长期最佳实践是否已变成教条。

- 🧠 区分“疯狂”和“愚蠢”：承诺做不到且不愿想办法是愚蠢；承诺后边做边解决，才是改变人生的疯狂。

### [我现在面试时会问的九个问题，真希望五年前就问过](https://louisedeason.substack.com/p/nine-questions-i-now-ask-in-interviews)

**原文标题**: [Nine Questions I Now Ask in Interviews That I Wish I'd Asked Five Years Ago](https://louisedeason.substack.com/p/nine-questions-i-now-ask-in-interviews)

面试本应是双向选择，但多数候选人把它当成考试；文章主张拒绝这种框架，利用面试尾声“你有什么问题”的环节反向考察公司。此时对方往往在回答而非评估，能暴露晋升路径、团队稳定性、诚实度、管理方式、招聘计划、未来同事、成败标准、重组历史和岗位空缺原因等关键信息；若公司因提问而抵触，反而用最低成本暴露了问题。

- 🎯 转变心态：面试不是单向考试，而是双向选择；有资历和选择权的候选人应主动“面试公司”。
- 📈 晋升路径：问最近一次晋升的具体案例、标准和时间；回答含糊或“近期没有”说明晋升路径不清晰。
- ⏳ 任期与去向：问该岗位任职最久的人待了多久、现在做什么，以判断人员流动和内部发展机会。
- 🕳️ 真实短板：问团队真正不擅长什么；具体诚实的回答比“凡尔赛式缺点”更有信息量。
- 🗣️ 分歧处理：问团队如何应对领导层决策分歧；健康团队有表达和反馈流程，而非一味“相信领导”。
- 👥 招聘计划：问未来 12 个月编制计划；不确定或未获批可能意味着团队未来仍在高层博弈。
- 🤝 未来同事：问最常合作的人是谁，并请求在流程中与其交流；安排是否顺畅本身就是信号。
- 🎯 成败定义：问六个月成功与失败分别是什么样；失败答案常暴露岗位的真实模糊性、政治性或倦怠风险。
- 🔄 重组历史：问最近一次重组时间与触发原因；频率和原因反映组织稳定性。
- ❓ 岗位空缺原因：直接问“为什么这个职位开放”；区分增长、补缺、重组，并注意回答是否迟疑。
- 🚪 反向筛选：若公司因这些问题不悦、敷衍或让你觉得自己“难搞”，说明它不愿被面试，应果断放弃。

### [如何变得更有野心：写给拥有模型的人类教程](https://felixrieseberg.com/how-to-be-more-ambitious-a-tutorial-for-humans-with-models/)

**原文标题**: [How to be more ambitious: A tutorial for humans with models](https://felixrieseberg.com/how-to-be-more-ambitious-a-tutorial-for-humans-with-models/)

文章作者在 Anthropic 工作，观察到模型能力在不同方向上发展不均衡：有些方面惊人，有些方面仍不足。很多人使用 AI 时仍停留在简单问答或润色邮件，没有充分发挥其潜力。作者提出从“速度、高度、深度、广度”四个维度提升使用 AI 的雄心，并解释人类为何常因自我设限而低估可能性。

- 🚀 模型能力并非均匀增长，关键在于学会驾驭其“惊人方向”，而不是只做基础任务。
- 🧭 作者将雄心分为四类：速度、高度、深度、广度；速度指同样工作更快完成，文章重点讨论后三者。
- 🎯 高度：从更高抽象层思考，关注最终结果而非单个任务，先问“接下来真正想发生什么”。
- 🛠️ 高度实践：不要只让模型填模板，而要给它足够业务数据，让它分析变化、原因与对策，甚至重新设计季度业务回顾流程。
- 🔁 高度还意味着建立可持续工作流，让模型脱离人工逐步喂任务，例如让 Claude 持续保证应用“无崩溃”，而非逐个修崩溃。
- 🔬 深度：要求模型使用领域顶尖专家的工具、方法、数据与知识，直到结果可能让专家也学到新东西。
- 📊 深度技巧：坚持使用数据库和统计模型而非表格；设定看似不合理但可解决的高目标；用原始数据挑战既有假设；让模型生成新知识。
- 🧪 深度实践：不要让模型自评，应使用外部工具或独立验证；可让模型先说明顶尖专家会怎么做、原始材料是什么、方法和验证方式是什么，再重写提示词。
- 🌐 广度：从多个领域引入视角、工具和技术，类似“劫案电影”中组建多元团队；多智能体系统让这种做法更可行。
- 🎭 广度方法：把名词换成动词，明确真正要完成的行为；组建“船员式”团队，如分析师、记者、编辑、红队、做空者、法务会计，但要让模型“做”其工作，而非角色扮演。
- 💻 实现这些雄心通常需要给模型一台可安装软件、访问相关数据的“计算机”，并通过 MCP 连接器或其他工具提供支持。
- 🧠 心理学依据：高自我效能感的人更相信自己，也完成更多；具体而困难的目标往往比“尽力而为”更有效。
- 🏃 案例说明：丹齐格误把未解统计题当作业解出、四分钟一英里被突破后多人跟进、Linux 以“只是爱好”起步，都说明相信可能、看到他人做到、允许失败能释放雄心。
