### [Figma 如何借助智能](https://www.figma.com/blog/how-figma-stays-ahead-of-vulnerabilities-with-agents/)

**原文标题**: [How Figma Stays Ahead of Vulnerabilities With Agents | Figma Blog](https://www.figma.com/blog/how-figma-stays-ahead-of-vulnerabilities-with-agents/)

Figma 安全团队通过构建基于 AI 代理的安全体系，在代码生成、PR 审查和历史代码审计三个阶段应用共享的威胁模型策略。文章详述了他们如何以高精度优先为原则，先建立 PR 审查机制，利用评估语料、人工反馈和自动化反馈循环持续提升漏洞检测的精确率与召回率，最终实现规模化漏洞防治。

- 🛡️ Figma 使用 AI 代理在代码生成、PR 审查和代码审计三个阶段防御漏洞，所有代理共享同一策略，该策略最终成为完整的威胁模型。
- 🔄 最先构建 PR 审查，因为它具备普适性、自助性和双向可观测性，能形成最快的改进循环。
- 🤖 同时运行 Claude Code 与 Codex 两种模型，因为它们会漏掉不同类型的 bug；每个 PR 审查中位成本约 $0.50。
- 📊 precision 是报告中的真实漏洞比例，recall 是真实漏洞中被捕获的比例；团队先提升 precision 再提升 recall。
- 🎯 初始 precision 仅 15%，团队设定 70% 目标后才向开发者开放评论；通过回放八周 PR 并手动标记误报，编写了包含 68 个先例的策略。
- 📜 策略以先例而非规则为主，例如“dbops 仅由已有数据库访问权的高特权操作员运行”，这保留了代理所需的安全推理。
- ✅ 一个月后 precision 提升到 80%，PR 审查成为合并要求；随后加入故障转移、重试、遥测和修复率追踪。
- 🧪 用 66 个真实漏洞作为评估集（46 个来自漏洞赏金，20 个来自内部）来测量 recall，采用通过率和按奖金加权两种评分；最新模型联合捕获率达 75.8%。
- 📈 去掉策略的裸模型按加权仅能捕获 44.4%，加入策略后升至 64.2%；precision 差距更大，但无法离线测量。
- 👥 precision 依赖生产环境中的开发者反馈：作者点赞/点踩，代理定期复核代码，争议案例送安全团队决断。
- 🔁 召回改进循环：赏金报告 → 代理验证与修复 → 加入评估集 → 复盘审查代理为何漏报 → 更新策略；误报也有类似的精度改进循环。
- 🕵️ 全仓库审计基于同一策略，通过分片、预算控制、剔除低严重性类别和对抗性复核，首次运行发现上百个潜在漏洞，其中两个为传统 SAST 漏掉的严重问题。
- 🪝 代码生成阶段使用 agent hooks 注入即时安全指导，例如新增 API 路由时强制读取授权指南；日志安全相关错误率降低约 50%。
- 💡 关键经验：先改进 precision 再改进 recall；precision 和 recall 需要不同信号；用带源码权限的代理快速分流漏洞赏金；让代理检查代码实践而不只是找漏洞。
